新潟・長野・群馬・岐阜・福井・兵庫の13スキー場について、今日と明日の予報をカードで比較するアプリ。CloudFrontが配信するHTMLにCSSとJavaScriptが含まれ、各地点の予報取得から雪質判定、カード描画までをブラウザーが担う。以下は2026年11月22日に取得した公開コードの静的解析に基づく。配信元サーバーの構成、デプロイ手順、実機でのオフライン動作は未確認。[公開アプリとHTML](https://d16oac9e0g58mg.cloudfront.net/)

## 起動から表示まで

1. 起動時に `loadAllResorts()` がブラウザーの保存データを読む。取得から30分未満なら結果を復元して描画する。
2. キャッシュの期限が切れている場合は読み込み中のカードを表示する。`RESORTS` に定義された全13地点の緯度・経度を使い、`fetchResortWeather()` が地点ごとにOpen-Meteoの予報APIを並列に呼ぶ。
3. 各地点の応答を今日と明日の2件に整形する。`Promise.allSettled` で全地点の処理が終わってから、成功データとエラーを地点ID別に保存する。一部の取得に失敗しても、成功した地点のカードは表示できる。
4. `renderCard()` が地点名と地域を描き、`renderDayCol()` が今日・明日それぞれの天気、最高・最低気温、雪質、夜間降雪量、日最大風速を表示する。地域ボタンは取得済みの一覧を絞り込む。更新ボタンは地域の選択にかかわらず全地点を再取得する。

## API応答を「今日・明日」に変換する

予報のタイムゾーンは `Asia/Tokyo`。`forecast_days=2` と `past_days=1` を指定し、日別配列の先頭3件を昨日・今日・明日として扱う。昨日のデータも要求するのは、今日の朝までに降った雪を集計するため。

| 入力 | アプリでの用途 |
| --- | --- |
| 日別の天気コード、最高・最低気温 | 天気アイコン、説明、気温表示、雪質判定 |
| 日別の降水量合計 | 湿雪の判定 |
| 地上10 mの日最大風速 | カードに整数の km/h で表示 |
| 時間別の降雪量 | 前日17:00から対象日09:00まで、両端の時刻を含む値を合計し、0.1 cm単位に丸める |

たとえば日曜の「夜間降雪」は土曜17:00から日曜09:00までの時刻に対応する値の合計。日曜の日中に降る雪はこの数値に入らない。時間別データまたは時刻配列が欠けると集計値は0になり、降雪量の個々の欠損値も0として扱う。

## 雪質と営業期間の判定

`getSnowQuality()` は条件を上から評価し、最初に一致したラベルを返す。下表の降雪量はすべて上記の夜間合計。「雪あり」は雪系の天気コード、または降雪量が0.5 cmを超える場合を指す。

| 順序 | 主な条件と結果 |
| --- | --- |
| 1 | 最高6°C以上、または最高4°C以上で雪なしなら「シャバ雪」。雨系の天気で最高1°C以上、または最高2°C以上・降水量5 mm超・雪なしなら「湿雪」 |
| 2 | 降雪25 cm以上かつ最高−1°C以下なら「極上パウダー」。15 cm以上かつ最高0°C以下、または8 cm以上かつ最高1°C以下なら「パウダースノー」 |
| 3 | 降雪4 cm以上かつ最高2°C以下なら「新雪」。1.5 cm以上かつ最高1°C以下なら「新雪（薄め）」 |
| 4 | 最高−4°C以下・降雪1 cm未満・雪なしなら「アイスバーン」。最低−8°C以下・最高1°C超・降雪0.5 cm未満なら「朝はアイス」 |
| 5 | 積雪深による分岐も実装されているが、現在の取得処理は `snowDepthM` を常に `null` にするため、この分岐には到達しない |
| 6 | 残りは最高気温で分類する。−1°C以下は「圧雪」、3°C以下は「湿雪」、それ以上は「シャバ雪」 |

たとえば夜間降雪10 cm・最高0°Cなら「パウダースノー」、同じ降雪量でも最高6°Cなら先頭の条件で「シャバ雪」になる。画面上の雪質は予報値からの推定。クローズ表示は別の関数 `isInSeason()` が端末の月日と地点ごとの例年の営業期間を照合して決める。年をまたぐ期間に対応し、開始日と終了日は営業期間に含む。実際のリフト運行状況は取得していない。

## キャッシュと障害時の表示

| 保存先 | 内容と動作 |
| --- | --- |
| localStorage / `ski_cond_v4` | 整形済み予報、地点別エラー、保存時刻を30分間再利用する。手動更新はこの読み出しをスキップする。全地点が失敗した結果も保存対象になる |
| Cache Storage / `ski-app-v2` | Service Workerがトップページ、HTML、マニフェスト、SVGアイコンを事前に保存する。画面の読み込みはキャッシュ優先。成功したAPI応答はリクエスト単位で保存する |

Service Workerがページを制御している場合、予報取得はネットワークを優先し、8秒で中断する。通信例外やタイムアウトでは同じリクエストの保存済み応答を返し、該当データがなければ503を返す。サーバーから届いたHTTPエラーはそのまま画面側の地点別エラー処理に渡る。[Service Worker](https://d16oac9e0g58mg.cloudfront.net/sw.js)

**更新時刻の読み方。** ヘッダーに出るのはアプリが一括取得を終えた時刻。API応答のキャッシュには有効期限がなく、手動更新でも通信失敗時には過去の応答が使われうる。日付をまたぐと、保存された予報の日付と「今日」「明日」のラベルがずれる可能性がある。

ホーム画面用のマニフェストは日本語、縦向き、スタンドアロン表示を指定する。192 pxと512 pxのPNGアイコンを宣言し、HTMLはApple端末向けにSVGアイコンも参照する。[マニフェスト](https://d16oac9e0g58mg.cloudfront.net/manifest.json)
